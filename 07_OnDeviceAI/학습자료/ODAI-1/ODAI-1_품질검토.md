# ODAI-1 설명자료 — 최종 품질 검토

검토 대상: [통합 설명자료](ODAI-1_설명자료.md), 6개 장별 문서, [학습 연결·복습 부록](ODAI-1_부록_학습연결과복습.md), [목차·작성 체크리스트](ODAI-1_목차와_작성체크리스트.md), `assets/ODAI-1`의 이미지·Canvas. 원본은 `삼성전자AI전문가교육-ODAI-1.pdf` 80쪽이다.

## 판단

**Part 1 교육생용 개념 설명자료로 사용할 수 있는 상태다.** 배정된 원본 페이지와 핵심 주제의 누락을 점검했고, 개념 간 연결에서 발견한 공백을 보완했다. 검토 범위 안에서 해결되지 않은 중대한 계산 오류나 필수 학습 연결의 단절은 발견하지 못했다. 이것은 모든 가능한 질문·실무 상황에 공백이 없다는 보증이 아니다.

## 작업과 검토의 분리

1. 주 에이전트가 80쪽의 추출 텍스트와 전체 페이지 시트를 분석하고 먼저 목차·장별 작성 체크리스트를 작성했다.
2. 하위 에이전트 3개가 각각 1–2장, 3–4장, 5–6장을 집필하고 자체 점검했다.
3. 이후 서로 집필하지 않은 장을 교차 검토했다. 1–2장 담당은 5–6장, 3–4장 담당은 1–2장, 5–6장 담당은 3장과 부록을 검토했다.
4. 주 에이전트가 6개 장 전체를 읽고 수식·계산·용어·원본 대응·장 사이 연결을 검토했다. 교차 검토 권고를 반영하고 4장 및 전체 문서 통합도 직접 점검했다.
5. 통합본에 페이지 찾아보기와 학습 연결 부록을 넣고 파일·렌더링 검사를 수행했다.
6. 추가 요청을 반영해 3장 최상단에 Linear / Nonlinear 분류 Canvas와 미리보기·해설표를 추가하고 통합본에도 반영했다.

## 지식의 공백 점검과 보완

| 점검한 연결 | 발견한 공백·오해 가능성 | 보완 결과 |
|---|---|---|
| DNN → Transformer → W/A/KV | 투영 가중치와 Q/K/V 값 혼동 | Q=XW_Q 등 생성식과 파라미터/활성값 구분 추가 |
| Prefill → decode → TTFT | 첫 생성 토큰의 출처 불명확 | prefill 마지막 위치에서 첫 토큰 선택 후 decode 반복 설명 |
| 파일 크기 → 실행 가능성 | weight payload만으로 RAM 예산 판단 | KV·활성값·workspace·runtime·OS 여유 설명 |
| 성능 수치 → 실제 응답 | TOPS·FLOP/s·tokens/s 혼동 | dtype·dense/sparse·MAC 계수와 지연 측정 경계 설명 |
| 공유 메모리 → peak 측정 | GPU VRAM과 시스템 RAM 중복 합산 | 전용·unified/shared 구분과 측정 양식 추가 |
| 비트 수 → 선형/비균일 표현 | INT4·FP4·NF4를 같은 숫자 형식으로 이해 | 3장 상단 분류 그림·표, PTQ/QAT·granularity 별도 축 설명 |
| PTQ → QAT | calibration과 전체 학습의 경계 혼동 | 데이터 역할, 최적화 대상, 학습 비용과 STE 설명 |
| OBQ → GPTQ | Hessian이 singular인 경우와 안정화 생략 | 양의 대각 damping과 λ 정의 추가 |
| 저장 양자화 → native 저비트 연산 | fake quant 결과를 실제 가속으로 해석 | Q/DQ·packing·fusion·fallback과 장치 측정 연결 |
| QAT → QLoRA | 기반 모델의 학습 여부 혼동 | 저장·계산·gradient 경로·실제 업데이트 대상 분리 |
| 개별 기법 → 선택 | 이름 암기로 끝날 가능성 | 병목별 시나리오, 독립 평가 자료와 측정 기록 양식 추가 |

## 가지치기 그림 추가 여부 판단

문서의 개념이 구성요소·기법 묶음으로 나뉘고, 가지를 따라 읽으면 본문에서 위치를 찾기 쉬운 경우에만 그림을 사용했다. 순서·인과·수치 비교·작업 상태가 핵심인 문서는 기존 흐름도·수식·표·목록을 유지했다.

| 문서 | 판단 | 적용 내용·이유 |
|---|---|---|
| 1장 AI 연산과 성능 | 추가하지 않음 | 연산 흐름, Roofline과 메모리 계산이 핵심. 하나의 분류 트리로 합치면 인과·단위 관계를 가릴 수 있음 |
| 2장 실행 환경 | 추가 | 모델·실행 소프트웨어·하드웨어의 구성 역할과 대표 예를 묶음. 구성 관계이며 실행 순서가 아님을 표시 |
| 3장 양자화 기초 | 기존 지도 유지 | Linear/Nonlinear 및 별도 VQ 가지가 이미 있어 추가 중복을 피함 |
| 4장 PTQ | 추가 | 범위·대표 입력, 반올림·재구성, 공유 단위·분포라는 오차 제어 관점을 묶음. 서로 조합 가능한 관점임을 표시 |
| 5장 QAT | 추가하지 않음 | forward·backward·업데이트의 반복 흐름이 핵심. 기존 QAT 흐름도와 비교표가 적합 |
| 6장 LLM 양자화 | 추가 | 추론 양자화의 분리·scaling·회전·재구성과 QLoRA의 미세조정 목적을 구별 |
| 학습 연결·복습 부록 | 추가하지 않음 | 장간 대응표·시나리오·색인·문제풀이가 중심이며 본문 지도와 중복됨 |
| 목차·작성 체크리스트 | 추가하지 않음 | 계층 목록·체크 상태를 직접 읽는 편이 명확 |
| 품질 검토서 | 추가하지 않음 | 판단 근거·검증 결과는 표가 적합 |
| 통합 설명자료 | 장별 그림 반영 | 2·4·6장에 추가한 그림을 본문 통합으로 반영하고 별도 중복 지도는 만들지 않음 |

새 그림은 각 장 상단에 배치하고 해당 절 번호와 읽는 법을 붙였다. 모든 가지가 배타적인 알고리즘 계열이라는 잘못된 인상을 피하도록 구성·관점·주된 수단이라는 분류 기준을 명시했다. 새 Canvas·PNG·SVG는 모두 `07_OnDeviceAI/assets/ODAI-1/`에 저장했다.

## 기계적·시각적 검증 기록

검증 상세는 [파일·페이지 검사 결과](../assets/ODAI-1/validation.json), [렌더링 검사 결과](../assets/ODAI-1/render-validation.json)에 저장한다. 통합본 HTML 미리보기는 `assets/ODAI-1/preview.html`이다. 최종 검사 결과의 숫자는 JSON을 기준으로 확인할 수 있다.

- 80쪽 이미지의 장별 대응 집합과 로컬 링크를 검사했다.
- Markdown 표의 열 구분자 불일치, 깨진 문자, 닫히지 않은 코드 블록을 검사했다.
- Microsoft Edge headless에서 통합 Markdown을 HTML로 변환한 결과를 열어 이미지 로드와 MathJax 수식 오류를 확인했다.
- 대표 장·수식/표 영역의 화면을 확인하고, Canvas 미리보기 7개에서 노드·화살표·텍스트 배치를 확인했다.
- Canvas 편집기 자체를 실행해 검증한 것은 아니다. `.canvas` 노드의 좌표·크기와 같은 좌표를 사용하는 PNG/SVG 미리보기를 검토했다.

통합본은 원본 페이지 이미지 80개와 흐름도·분류도 7개, 총 87개의 인라인 이미지를 포함한다. 전체 맥락 Crop 80개는 링크로 제공한다. 표는 52개이며 최종 로컬 링크 수·수식 렌더링 수·오류 여부는 위 JSON에 기록한다.

추가 분류도 검토에서 VQ를 Non-uniform 스칼라의 엄밀한 하위집합으로 두지 않고 **벡터 공동 부호화라는 별도 가지**로 분리했다. Binary-code도 계수 선택에 따라 균일해질 수 있으므로 강의의 비균일 예제로 한정했다. 문서가 `07_OnDeviceAI/ODAI-1/`로 이동된 뒤 이미지·원본 PDF·부속 파일 상대 경로를 다시 검사했다.

## 검증의 한계

이번 작업은 문서 제작·검토다. 실제 모델 양자화, NPU 배포, 정확도 벤치마크나 장치 속도·전력 측정은 수행하지 않았다. 따라서 문서의 실습 기록 양식에는 실제 측정값을 채우지 않았다. 수식 표시에는 수학 렌더링을 지원하는 Markdown 뷰어가 필요하며, HTML 검토 미리보기의 MathJax는 외부 CDN을 사용한다. 원본 Crop·PNG 흐름도는 로컬 파일이므로 별도 수식 렌더러 없이 볼 수 있다.

통합본은 자동 조립 결과다. 향후 수정은 장별 MD 또는 부록에서 한 뒤 `assets/ODAI-1/build_and_check.py`를 실행해 반영한다. 새 페이지·이미지·Canvas를 추가하면 검증 JSON과 이 검토서를 함께 갱신한다.
