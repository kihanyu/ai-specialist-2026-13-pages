8. 종합 복습: 조건에 맞는 수단을 선택하기

학습 안내 · 이전 · 원문 대응과 검토

이 문서는 원문 전체를 연결하는 교육용 보충이다. 아래 시나리오의 조건·숫자는 원문 실험 결과가 아니다. 본문에서 배운 원리로 선택 이유와 필요한 검증을 설명하는 데 사용한다.

8.1 먼저 목적과 제약을 적기

“빠른 모델” 대신 정해진 입력 길이·동시 요청 수에서 품질 하한을 지키면서 지연시간과 최대 메모리를 줄인다고 목표를 쓴다. 모바일 단일 요청 지연과 서버 다중 요청 처리량은 다른 목표일 수 있다.

기록 예시 또는 기록할 값
입력과 생성 조건 batch, prompt 길이, 최대 출력 길이, decoding 방식
품질 기준 같은 검증셋 정확도·PPL·과제 성공률과 허용 하락폭
장치·runtime 장치 모델, 메모리, OS, backend·라이브러리 버전
기준 모델 모델 revision, dtype, KV dtype, attention 구현
속도 초기 응답 시간(TTFT), token 간 지연(ITL), 전체 시간, 처리량
메모리 가중치 본체, KV, activation, workspace, 실제 peak
측정 절차 warm-up, 반복 수, 동기화, 전원·온도 조건

**TTFT(Time To First Token)**는 요청 시작부터 첫 token까지의 시간, **ITL(Inter-Token Latency)**은 연속 출력 token 간 시간이다. 전처리·대기열 포함 여부도 함께 기록한다. **PPL(perplexity, 혼란도)**은 같은 데이터·tokenizer·평가 조건에서 낮을수록 좋은 언어모델 예측 지표이며 다른 조건 간 직접 비교는 피한다.

8.2 적용 시나리오

A. 비구조적 70% 희소 모델인데 속도는 그대로다

확인 순서 판단
실제 사용 커널 확인 Dense 커널이면 원래 크기대로 계산할 수 있음
Sparse 커널 비용 확인 인덱스 처리·불규칙 접근·작은 행렬의 부가 비용 점검
대안 비교 채널 가지치기로 작은 dense 연산을 만들 수 있는지 검토

돌아갈 곳: 2장. 희소 패턴 → 압축 표현 → 지원 커널 → 실제 실행 여부를 연결해 설명한다. 대안의 품질도 다시 평가한다.

B. 긴 문맥에서 메모리가 넘친다

조건 선택·주의
KV가 실제 메모리의 큰 부분 KV 양자화·퇴거 검토
모든 문맥 보존 필요 영구 퇴거가 중요한 정보를 잃는지 평가
저장량보다 읽기 대역폭이 병목 Quest 같은 읽기 선택 검토

돌아갈 곳: 5장. 먼저 peak 메모리를 가중치·KV·activation·임시 공간으로 나눠 본다. 읽기만 줄이는 방법이 cache 전체 저장량도 줄인다고 가정하지 않는다.

C. 작은 학생의 품질이 낮고 교사 응답만 얻을 수 있다

  • 가능한 학습: 교사 응답을 모범 데이터로 사용하는 sequence/response KD.
  • 부족한 정보: 응답 문자열만으로 전체 어휘의 token-level KL을 정확히 계산할 수 없음.
  • 확인할 품질: 교사 응답의 오류, 데이터 중복, 과제 편향.

돌아갈 곳: 4장. 작은 구조를 준비하는 일과 좋은 학습 신호를 제공하는 일을 구분한다.

D. 단일 요청 decode에서 큰 모델 호출이 비싸다

  • 후보 방법: 투기적 디코딩.
  • 측정 항목: 초안 시간, 검증 시간, 실제 연속 수용 길이.
  • 조건 변화: 동시 요청이 늘면 검증이 처리 용량을 차지해 결과가 달라질 수 있음.
  • 분포 보존 요구: 수용·잔차 보정·KV cache 관리 조건 확인.

돌아갈 곳: 6장. 긴 초안과 높은 수용률만으로 가속을 판정하지 않는다.

E. 가중치는 작은데 초기 activation이 SRAM을 넘는다

  • 원인 후보: 동시에 필요한 중간 활성값이 너무 큼.
  • 후보 방법: 메모리 재사용 계획, patch 실행.
  • 절충: Peak 활성값 감소와 halo 중복 계산 증가.

돌아갈 곳: 7장. 가중치 정밀도를 줄이는 방법이 모든 실행 메모리 문제를 해결하지는 않는다.

8.4 종합 문제

해설을 열기 전에 식·중간값·가정을 적는다.

  1. 원래 dense FP16 행렬이 1000×1000이다. 80%를 0으로 만들고 비영 값은 FP16, column index와 row pointer는 각각 32비트로 CSR 저장한다. 배열 header·padding을 제외한 byte 수와 dense 대비 비율은?
  2. OBS에서 $w_q=0.4$, $[H^{-1}]_{qq}=2$라면 q번째 업데이트와 근사 손실 증가를 구하라. 역헤시안 q번째 열 전체를 모르면 다른 가중치 업데이트까지 계산할 수 있는가?
  3. KV 설정이 32 layer, B=2, L=8192, KV head=8, head dimension=128, FP16일 때 본체는 몇 GiB인가? metadata를 무시하고 4 bit로 바꾸면?
  4. SD에서 일정 수용률 a=0.5, 초안 길이 3, 초안 1개 1ms, 검증 전체 8ms, 기준 목표 1-token 10ms라면 예상 가속률은?
  5. [1,4,2]와 [2,3,5]의 softmax를 각각 정규화해 합치면 어떤 오류가 있는가? 같은 최대·분모를 구하는 식을 적어라.
  6. 출력 patch를 반으로 나누면 메모리도 절반이고 연산량도 절반이라는 주장의 문제를 설명하라.
종합 해설
  1. nnz=200,000. CSR은 $200000(2+4)+1001\times4=1,204,004$ byte, dense는 2,000,000 byte다. 비율은 약 **60.2002%**다. 20% 밀도라고 저장량도 20%가 되는 것은 아니다. 2장 2.3으로 돌아간다.
  2. $\Delta w_q=-0.4$여서 제거 후 0, 근사 손실 증가는 $0.4^2/(2\times2)=0.04$다. 다른 성분을 구하려면 역헤시안 열의 해당 성분도 알아야 한다. 3장 3.3을 확인한다.
  3. $2\times32\times2\times8192\times8\times128\times2=2,147,483,648$ byte=2 GiB다. 4 bit 본체는 0.5 GiB다. KV scale·고정밀 residual·정렬·전체 실행 메모리는 별도다. 5장 5.6을 확인한다.
  4. 기대 확정 길이는 $1+0.5+0.25+0.125=1.875$, 라운드는 11ms다. 시간/token은 약 5.8667ms, 가속률은 $10\times1.875/11\approx1.7045$배다. 이론적 설명용 가정이며 실측은 아니다. 6장 6.3을 확인한다.
  5. 각 타일 합이 1이어서 결합하면 합이 2다. $m=\max(m_a,m_b)$, $l=e^{m_a-m}l_a+e^{m_b-m}l_b$로 전체 분모를 맞춘다. 7장 7.4를 확인한다.
  6. layer를 넘는 의존성·출력 조립·halo가 남고 경계 입력을 중복 처리할 수 있다. peak 메모리와 전체 연산량은 별개다. 7장 7.5를 확인한다.
